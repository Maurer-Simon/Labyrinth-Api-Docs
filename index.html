Das Verrückte Labyrinth – Offizielle API v2.0 Standard

Schnittstellendokumentation für den Verzeichnisserver (REST) und die verteilte Spielserver-Kommunikation (JSON-over-WebSocket).
Envelope-Format: Jede WebSocket-Nachricht nutzt strikt {"type": "...", "data": {...}}.
Eingänge-Prinzip: Kacheln definieren Wege via entrances: ["UP", "DOWN", "LEFT", "RIGHT"].
Koordinaten: Ursprung (0,0) oben links. Feldnamen: "row" und "column".
Reconnect-Token: Bei CONNECT_ACK erhaltenes identifierToken ermöglicht 30s-Reconnect.
Client-KI: KI-Logik rechnet rein clientseitig; Server trackt & loggt Status per isAiControlled.
Siegbedingung: Alle Schätze finden + Rückkehr auf das homePosition-Startfeld.
1. Verzeichnisserver (REST API)
POST /api/servers Spielserver beim Verzeichnisserver registrieren
REST
▶
Wird vom Spielserver beim Hochfahren aufgerufen, damit Clients ihn finden können.
Request Body
FeldTypPflichtBeschreibung
namestringjaName des Spielraums (z. B. "MCI Labyrinth Server 1")
hoststringjaIP-Adresse oder Domain des Spielservers
portintegerjaPort des WebSocket-Servers (z. B. 9000)
maxPlayersintegerjaMaximale Spieler (2–4)
boardSizeobjectoptional{"rows": 7, "cols": 7}
Beispiel Request
{
  "name": "MCI Arena #1",
  "host": "192.168.1.100",
  "port": 9000,
  "maxPlayers": 4,
  "boardSize": { "rows": 7, "cols": 7 }
}
Antworten: 201 Created: { "serverId": "srv-44a1", "heartbeatIntervalSeconds": 10 } 400 Bad Request: { "error": "INVALID_CONFIG" }
GET /api/servers Liste aller verfügbaren Spielserver abrufen
REST
▶
Wird vom Client beim Programmstart aufgerufen, um aktive Partien zur Auswahl anzuzeigen.
Query Parameter
ParameterTypPflichtBeschreibung
statusstringoptionalFilter nach Status: LOBBY oder RUNNING
Beispiel Response (200 OK)
[
  {
    "serverId": "srv-44a1",
    "name": "MCI Arena #1",
    "host": "192.168.1.100",
    "port": 9000,
    "currentPlayers": 2,
    "maxPlayers": 4,
    "status": "LOBBY"
  }
]
PUT /api/servers/{id}/heartbeat Lebenszeichen & Spielerstand des Servers aktualisieren
REST
▶
Server senden diesen Request alle 10 Sekunden. Bleibt der Heartbeat aus, wird der Server nach 30s automatisch entfernt.
Request Body
{
  "status": "RUNNING",
  "currentPlayers": 3
}
Antworten: 200 OK: { "acknowledged": true } 404 Not Found: { "error": "SERVER_NOT_FOUND" }
DELETE /api/servers/{id} Spielserver sauber aus Verzeichnis austragen
REST
▶
Wird beim Herunterfahren des Spielservers aufgerufen.
Antworten: 204 No Content 404 Not Found
2. Client → Server (Commands)
SEND CONNECT Lobby beitreten oder bestehende Spielsession wiederaufnehmen
LOBBY
▶
Muss innerhalb von 10s nach WebSocket-Verbindung gesendet werden. Bei Reconnect wird das zuvor erhaltene identifierToken mitgesendet.
Data-Felder
FeldTypPflichtBeschreibung
usernamestringjaSpielername (1–50 Zeichen)
identifierTokenstringoptionalReconnect-Token für Wiederverbindung
Beispiel – Erstverbindung
{
  "type": "CONNECT",
  "data": {
    "username": "Alice"
  }
}
Folge-Events: CONNECT_ACK (Unicast) LOBBY_STATE (Broadcast) ERROR (LOBBY_FULL, USERNAME_TAKEN)
SEND DISCONNECT Verbindung zur Lobby oder laufenden Partie sauber beenden ▶ 
{
  "type": "DISCONNECT",
  "data": {}
}
SEND START_GAME Spiel starten & konfigurieren (nur Admin/Spielleiter, min. 2 Spieler)
ADMIN
▶
FeldTypPflichtBeschreibung
boardSizeobjectja{"rows": 7, "cols": 7} (ungerade Zahlen 3–11)
treasureCardCountintegeroptionalSchatzkarten pro Spieler (Standard: 6, max: (rows*cols-4)/players)
gameDurationInSecondsintegeroptionalSpielzeitlimit (0 = unbegrenzt, Standard: 3600)
totalBonusCountintegeroptionalGesamtzahl Boni im Spiel (0–20, Standard: 4)
 
{
  "type": "START_GAME",
  "data": {
    "boardSize": { "rows": 7, "cols": 7 },
    "treasureCardCount": 6,
    "gameDurationInSeconds": 1800,
    "totalBonusCount": 4
  }
}
Folge-Events: GAME_STARTED (Broadcast) NEXT_TREASURE (Unicast pro Spieler) ERROR (NOT_ADMIN, NOT_ENOUGH_PLAYERS)
SEND ROTATE_SPARE_TILE Ersatzkachel um 90° im Uhrzeigersinn drehen
WAITING_FOR_PUSH
▶
Nur erlaubt, wenn der Spieler am Zug ist und in Phase WAITING_FOR_PUSH. Rotiert die Eingänge der Kachel (z. B. ["UP", "RIGHT"] $\to$ ["RIGHT", "DOWN"]).
{
  "type": "ROTATE_SPARE_TILE",
  "data": {}
}
Folge-Events: GAME_STATE_UPDATE (mit aktualisierter spareTile) ERROR (NOT_YOUR_TURN, INVALID_ACTION)
SEND PUSH_TILE Ersatzkachel in eine Zeile oder Spalte einschieben
WAITING_FOR_PUSH
▶
Regeln beim Schieben:
1. rowOrColIndex darf regulär nur ungerade sein (1, 3, 5 bei 7x7).
2. Rückschiebe-Verbot: Das direkte Rückgängigmachen des Vorzugs (z. B. Vorher: Row 1 RIGHT $\to$ Verboten: Row 1 LEFT) ist ungültig!
FeldTypPflichtBeschreibung
rowOrColIndexintegerjaZeilenindex (bei LEFT/RIGHT) oder Spaltenindex (bei UP/DOWN)
directionDirectionja"UP", "DOWN", "LEFT", "RIGHT"
 
{
  "type": "PUSH_TILE",
  "data": {
    "rowOrColIndex": 1,
    "direction": "RIGHT"
  }
}
Folge-Events: GAME_STATE_UPDATE (state wechselt auf WAITING_FOR_MOVE) ERROR (INVALID_PUSH, NOT_YOUR_TURN)
SEND MOVE_FIGURE Spielfigur entlang zusammenhängender Gänge ziehen
WAITING_FOR_MOVE
▶
Regeln beim Ziehen: Zielfeld muss über offene Pfade erreichbar sein. Beim Laufen darf über andere Figuren hinweggezogen werden. Zwei Figuren dürfen nie auf demselben Feld stehen bleiben!
FeldTypPflichtBeschreibung
targetCoordinatesCoordinatesja{"row": 3, "column": 4}
 
{
  "type": "MOVE_FIGURE",
  "data": {
    "targetCoordinates": { "row": 3, "column": 4 }
  }
}
Folge-Events: GAME_STATE_UPDATE (Nächster Spieler ist dran) TREASURE_FOUND (falls Schatzfeld erreicht) BONUS_COLLECTED (falls Bonusfeld betreten) ERROR (INVALID_MOVE, POSITION_OCCUPIED)
SEND PASS_MOVE Figur nicht bewegen (stehenbleiben) und Zug beenden
WAITING_FOR_MOVE
▶ 
{
  "type": "PASS_MOVE",
  "data": {}
}
SEND USE_BONUS Gesammelten Bonus aus dem Inventar aktivieren
BONUS
▶
Der Bonus muss im Inventar (availableBonuses) vorhanden sein. Jeder Bonus ist genau 1x nutzbar.
FeldTypPflichtBeschreibung
bonusTypeBonusTypeja"BEAM", "SWAP", "PUSH_FIXED", "PUSH_TWICE"
paramsobjectjaSpezifische Aktionsparameter nach Typ (siehe Beispiele)
Beispiele nach BonusType
// 1. BEAM: Figur auf beliebiges freies Feld teleportieren
{
  "type": "USE_BONUS",
  "data": {
    "bonusType": "BEAM",
    "params": { "targetCoordinates": { "row": 5, "column": 2 } }
  }
}

// 2. SWAP: Eigene Figur mit anderer Figur tauschen
{
  "type": "USE_BONUS",
  "data": {
    "bonusType": "SWAP",
    "params": { "targetPlayerId": "p-9812" }
  }
}

// 3. PUSH_FIXED: Einmalig feste (gerade) Reihe schieben (außer Rand 0 und max)
{
  "type": "USE_BONUS",
  "data": {
    "bonusType": "PUSH_FIXED",
    "params": { "rowOrColIndex": 2, "direction": "DOWN" }
  }
}

// 4. PUSH_TWICE: Zweites Mal schieben (setzt Phase von WAITING_FOR_MOVE auf WAITING_FOR_PUSH)
{
  "type": "USE_BONUS",
  "data": {
    "bonusType": "PUSH_TWICE",
    "params": {}
  }
}
Folge-Events: BONUS_USED (Broadcast) GAME_STATE_UPDATE ERROR (BONUS_NOT_AVAILABLE, INVALID_BONUS_TARGET)
SEND SET_AI_MODE Server über Aktivierung/Deaktivierung der Client-KI informieren
CLIENT-KI
▶
Die KI wird vollständig im Client gerechnet. Der Server führt keine Züge aus, sondern loggt den Status mit und setzt isAiControlled im Spielerprofil.
{
  "type": "SET_AI_MODE",
  "data": {
    "enabled": true
  }
}
Folge-Event: PLAYER_UPDATED (Broadcast)
SEND REMATCH_REQUEST Nach Spielende Zusage für die nächste Runde abgeben ▶
Vorherige Spieler haben Vorrang. Nach Ablauf eines Timeouts (15s) wird die Lobby für externe Neuanmeldungen geöffnet.
{
  "type": "REMATCH_REQUEST",
  "data": {
    "ready": true
  }
}
3. Server → Client (Events & Antworten)
UNICAST SERVER_INFO Sofort nach TCP/WebSocket-Handshake – signalisiert Empfangsbereitschaft ▶ 
{
  "type": "SERVER_INFO",
  "data": {
    "serverVersion": "2.0.0",
    "serverTime": "2026-09-15T18:00:00Z",
    "motd": "Willkommen am MCI Labyrinth Server!"
  }
}
UNICAST CONNECT_ACK Bestätigung der Verbindung mit ID, Farbe und Reconnect-Token ▶
WICHTIG: Das identifierToken muss vom Client gespeichert werden, um nach Verbindungsabbrüchen reconnecten zu können.
{
  "type": "CONNECT_ACK",
  "data": {
    "playerId": "p-101",
    "username": "Alice",
    "playerColor": "RED",
    "isAdmin": true,
    "identifierToken": "token-98f2-4bc1-912a"
  }
}

BROADCAST GAME_STARTED Initialer Aufbau des Spielfelds zum Start der Partie ▶
Überträgt das gesamte Spielfeld mit Eingängen (entrances) pro Kachel und das freie Plättchen. Direkt im Anschluss erhält jeder Spieler per Unicast sein NEXT_TREASURE.
{
  "type": "GAME_STARTED",
  "data": {
    "rows": 7,
    "cols": 7,
    "gameEndTime": "2026-09-15T19:00:00Z",
    "spareTile": {
      "entrances": ["UP", "RIGHT"],
      "treasure": null,
      "bonus": null,
      "isFixed": false
    }
  }
}
UNICAST NEXT_TREASURE Geheime Schatzkarte (nur an den jeweiligen Spieler!) ▶
GEHEIM: Wird ausschließlich per Unicast an den berechtigten Spieler gesendet. Andere Spieler sehen nur den Zähler remainingTreasureCount im State.
{
  "type": "NEXT_TREASURE",
  "data": {
    "treasureId": 4,
    "name": "Goldene Krone",
    "remainingTreasureCount": 5
  }
}

      {
        "playerId": "p-101",

  }

FEHLER ERROR Befehl abgewiesen oder Regelverstoß (Unicast an Verursacher) ▶
Unicast nur an den betroffenen Client. Der Spielzustand am Server bleibt unverändert.
{
  "type": "ERROR",
  "data": {
    "errorCode": "INVALID_MOVE",
    "message": "Zielfeld ist über offene Pfade nicht erreichbar.",
    "correlationType": "MOVE_FIGURE"
  }
}
